# Whole-city local map

The `sf` build uses the complete San Francisco source bounds, `[-122.527, 37.703, -122.348, 37.833]` in west/south/east/north order. Its snapped world bounds are `[-10752, -5632, 5376, 9216]`, covering 3,654 tiles of 256 metres. The current Ferry–Lombard corridor keeps two detailed visual LODs. Remaining tiles use one coarse visual LOD, source building footprints and a road-carved terrain heightfield. All generated inputs, maps and evidence stay in ignored output directories.

## Reproduce

Install the existing map workspace dependencies and `osmium-tool`. Obtain a San Francisco PBF covering the full requested bounds; `--area sf` deliberately refuses a citywide Overpass query. This run uses the [BBBike San Francisco extract](https://download.bbbike.org/osm/bbbike/SanFrancisco/), snapshot `2026-09-25T23:00:00Z`, with MD5 `7876c72db76e82de580f644e19d8b596`. Its source polygon contains the complete map bounds. Keep the original PBF alongside the cache so OSM route relations remain available to transit tools.

From the repository root:

```sh
npm --workspace @gtasf/map run fetch -- --area sf --osm-pbf tools/map/out/SanFrancisco.osm.pbf
npm --workspace @gtasf/map run build -- --area sf --osm-pbf tools/map/out/SanFrancisco.osm.pbf
npm --workspace @gtasf/map run validate -- --area sf
```

The cache also contains DataSF building footprints, Terrain Tiles elevation and sourced neighbourhood polygons. Subsequent builds work offline. Unused regional boundary relations may extend outside the PBF; incomplete building geometry and routing restrictions remain strict errors.

For an isolated local preview use `GTASF_MAP_AREA=sf`. To select a fully validated map as the default local build:

```sh
npx tsx tools/map/src/pipeline/cli.ts activate --area sf --local-only
npm run dev
```

Activation requires artifact validation. Normal activation also requires the compressed map budget to pass. The explicit `--local-only` option records an over-budget local-v1 selection under the founder override in `AGENTS.md`; it does not authorize production upload or satisfy payload acceptance. Selection writes `tools/map/out/active-map.json` atomically; the next dev or preview server reads it once. The historical `/map/lombard/` URL is stable for radar, props and cinematic clients. An incomplete bake never selects itself. Existing running dev servers retain their selected map until restarted. Client and Worker must use the paired city road graph before changing the shared local default.

## Geometry and streaming changes

- Intersecting road ribbons share one rendered surface. Ground under surface roads is cut away, preventing coplanar road/terrain overlap.
- Broadway's sourced tunnel gets an open-ended wall/ceiling shell and terrain portal cuts. Buildings spanning tunnel passages retain their upper and lower mass, with mesh and collision split around the bore. Road contact respects the player's current elevation instead of selecting a ground road above the tunnel.
- The Bay Bridge western approach and attached ramps use a shared-endpoint deck correction to clear the Rincon Hill DEM. These are approximate game elevations, not surveyed bridge heights.
- Coarse and detailed terrain retain identical 4 m border samples after triangulation.
- Each decoded map primitive is capped at 64 KiB. The client reveals one primitive per frame and serializes scene construction; meshopt decoding continues in workers. Chunk selection uses direct grid lookups.
- Graph compaction preserves lane connectivity, OSM identities, controls and continuation lists. Redundant geometric samples have a maximum 2 cm simplification error. The runtime uses one `roadpack-v1` binary containing the full contact graph and a collision-cleared routing mask. Audit JSON remains in the output directory but is not referenced by the runtime manifest.
